## 04 · 自研路线图：做一个"自己的 UU 远程"

### 0. 先想清楚：做到哪一步

| 路线 | 做法 | 耗时 | 效果 |
|---|---|---|---|
| A 组装 | **Sunshine（被控）+ Moonlight（控制）** 做串流，**Tailscale/Headscale 或 ZeroTier** 打洞组网，国内 VPS 自建 DERP/中继兜底 | 1 天 | 体验接近 UU，4K120 无压力 |
| B 半自研 | 自己写打洞 + 中继 + 信令，串流仍用 Sunshine/Moonlight 或 ffmpeg/GStreamer | 数周 | 完全掌握网络层 |
| C 全自研 | 采集/编码/传输/控制全部自己写 | 数月 | 学到最多，也最难 |

建议：**先做 A 当日用工具，同时按 B→C 的顺序学习。** 你已经有 Go 环境，网络层用 Go（pion）非常合适。

### 1. 系统架构（自研版）

```
 [信令服务器]  WebSocket，账号/设备/房间，交换 SDP 与 ICE 候选      ← 小 VPS 就够
 [STUN]        可用公共的（stun.miwifi.com 等），也可以自建在信令机上
 [TURN 中继]   coturn，部署在国内 BGP VPS                          ← 唯一花钱的地方
 [被控端]      采集 → 硬件编码 → 打包/FEC → UDP  ；  接收输入 → SendInput / uinput
 [控制端]      UDP → 抖动缓冲 → 硬解 → 渲染     ；  采集键鼠 → DataChannel
```

### 2. 分阶段任务

#### 阶段 1 · 网络层（本目录 `lab/` 已起步）
- [x] 手写 STUN 客户端，探测 NAT 映射行为（`lab/stunprobe`）
- [x] 会合服务器 + UDP 打洞 + RTT + 保活（`lab/punch`）
- [ ] 在 VPS 上跑 `punch server`，分别在家宽/手机热点测试打洞成功率
- [ ] 加 IPv6 候选；加 RFC 5780 过滤行为探测
- [ ] 用 pion/ice 替换手写实现，再对比两者差异
- [ ] 部署 coturn，实现"P2P 超时 → 自动降级 TURN"
- [ ] 加密：DTLS 或 Noise 协议（WireGuard 用的就是 Noise）

#### 阶段 2 · 媒体管线
- [ ] 先用 ffmpeg 验证：`gdigrab`/`ddagrab`（Windows）或 `kmsgrab`/PipeWire（Linux）→ `h264_nvenc -tune ull -bf 0` → 通过 UDP 发出
- [ ] 换成原生 API：DXGI Desktop Duplication + NVENC/AMF/QSV，GPU 纹理零拷贝
- [ ] 测出每一环的耗时，画出延迟预算表（对照 01 §3.3）

#### 阶段 3 · 传输协议（远控的核心竞争力）
- [ ] 视频帧切成 ~1200 字节的分片（低于 MTU，避免 IP 分片）
- [ ] NACK 重传 + Reed-Solomon/XOR FEC，按丢包率动态调整冗余
- [ ] 带宽估计 + 码率自适应（参考 WebRTC GCC，或者直接用 pion 的 interceptor）
- [ ] 丢关键帧时请求 IDR，或者用 intra-refresh 让码率更平滑
- [ ] 输入走可靠通道（DataChannel 或 QUIC stream），视频走不可靠通道

#### 阶段 4 · 产品化
- [ ] 虚拟显示器（"超级屏"：Windows 用 IddCx 驱动，参考开源的 Virtual-Display-Driver）
- [ ] 剪贴板、文件传输、音频（WASAPI loopback + Opus）
- [ ] 安全：设备认证、端到端加密、连接确认

### 3. 值得读的开源项目

| 项目 | 学什么 |
|---|---|
| **RustDesk** | 最接近 UU 的完整开源远控：会合服务器 hbbs、中继 hbbr、NAT 类型检测、打洞逻辑 |
| **Sunshine / Moonlight** | 低延迟采集、编码、FEC、视频分片——串流部分的最佳参考 |
| **pion/webrtc, pion/ice**（Go） | 纯 Go 实现的完整 WebRTC，代码清晰，适合读 |
| **libjuice / libdatachannel**（C） | 轻量 ICE 与 WebRTC，适合嵌入原生客户端 |
| **Tailscale magicsock / DERP** | 工业级打洞、端口喷洒、中继回退 |
| **coturn** | TURN 服务器 |
| **uulink** | 别人对 UU 远程协议做的逆向，用来对照理解（只用于学习，不要拿它长期跑网易的中继） |

### 4. 成本估算

- 信令 + STUN：1 核 1G 的 VPS 就行，每月几十元。
- TURN：国内 BGP 带宽贵，一路 1080p60 约 20~40Mbps。**所以 P2P 成功率每提高 1%，都是实打实地省钱**——UU 能免费的根本原因就在这里。个人自用的话，中继可以只开 5~10Mbps 当保底。
