# 设计：P2P 直传给朋友用（通讯录模式 + 四平台客户端）

图：[27-flow-pairing](27-flow-pairing.mmd)（加好友）、[34-contacts](34-contacts.mmd)（通讯录和各端客户端），总览里的 `contacts`、`desk` 节点。
上一份设计（先体检、再直传，已完成）归档在 [designs/2026-11-21-preflight.md](designs/2026-11-21-preflight.md)。

## 目标

把 p2pcp 从「我自己的一台手机 ↔ 一台电脑」做成**我和朋友都能直接用的传文件工具**：朋友装上就能用，不用懂打洞、不用配服务器；
加好友扫一次码（或者微信发一段邀请码），之后选人就能发，对方自动收。能直连就直连，打不通走 99-server 中继，并在后台升级回直连（上一份设计已做好）。

## 决策

1. **平台：安卓、Windows、macOS、Linux，不做 iPhone。**（用户定，2026-11-21）iOS 不能侧载，要 99 美元/年的开发者账号走 TestFlight，后台常驻接收也受限。
2. **通讯录模式代替「打包时写死的房间密钥」。**（默认）每台设备第一次运行生成设备密钥（X25519，Go 标准库 `crypto/ecdh`）和设备名；每一对好友的房间密钥 = `HKDF(ECDH(我的私钥, 对方公钥), "p2pcp pair")`，两边算出来一样，线路上不出现。会合服务器、打洞、QUIC 认证都不用改：配对密钥直接当现在的「房间密钥」用。我自己的电脑和手机也只是通讯录里的两个联系人，旧的 `room` 文件和 `.pc` / `.phone` 两个房间退役（自己的设备重新加一次好友，不做迁移）。
3. **加好友 = 一次性邀请码，扫一次两边就互相加上。**（默认）邀请码 = 会合地址 + 128 位一次性密钥，写成 `p2pcp://join/<base32>`，可以当文字发微信，也可以显示成二维码当面扫。被邀请方用这个密钥当房间密钥，和邀请方会合、打洞、QUIC 认证（现有流程），然后在 ALPN `p2pcp-pair/1` 上互换名片（设备名 + 公钥），各自算出配对密钥、写进通讯录，邀请码作废。128 位是因为会合服务器看得到房间号（密钥的 HMAC），密钥短了能被离线穷举。
4. **邀请码 24 小时有效，由邀请方的常驻接收在后台等。**（默认）微信发过去，朋友可能过几个小时才点；不要求两边同时开着界面。用过一次或过期就删。
5. **会合地址跟着邀请码走，存进每个联系人。**（默认）朋友零配置；以后不同的朋友圈子可以用不同的服务器。默认都是 99-server（会合 7001 / 7000，中继 3478，出方向 3M 大家共用）。
6. **好友发来的文件自动接收，按好友分目录**（`下载/P2P直传/<好友名>/`），弹通知。（默认）只有通讯录里的人进得了配对房间，不再逐个确认。
7. **常驻接收 `serve` 同时听所有好友的房间和没用掉的邀请**：每个房间一个 socket，以 `recv` 身份注册（现有 `keepServing`）。（默认）几十个好友以内没问题；再多就要改成「一个收件房间 + 连上后再认人」，先不做（待定）。
8. **核心逻辑都放在 Go 的 p2pcp 里，各端界面只是薄壳。**（默认）新命令：`p2pcp id`（看 / 改设备名）、`invite`（出邀请码）、`join <码>`、`contacts`（列出 / 删除）、`send -to <好友> 文件…`、`serve`。界面照现在的方式启动它、读 `-progress` 的 `@` 行。四个平台共用一份实现。
9. **桌面版（Windows / macOS / Linux）是一个本地网页界面：`p2pcp app`。**（默认）同一个进程里跑 `serve`，加一个只听 `127.0.0.1` 的小 HTTP 服务（HTML 内嵌进二进制），自动打开浏览器：通讯录、加好友（显示二维码 / 粘贴邀请码）、选文件发送、收发记录。纯 Go、`CGO_ENABLED=0`，一条命令交叉编译出三个平台；不用 Fyne / Wails 这类要 cgo 的 GUI 库。网页里选的文件要先经本机 HTTP 传给 p2pcp（和安卓 App 先复制到缓存一样），大文件主要靠右键发送。
10. **桌面系统集成按平台各做一份**（默认）：开机自启（Windows 启动文件夹快捷方式 / macOS `~/Library/LaunchAgents` / Linux systemd 用户服务）；右键发送（Windows「发送到」文件夹 / Linux Dolphin 菜单，macOS 先不做、用网页选文件）；通知（Windows PowerShell toast / macOS `osascript` / Linux `notify-send`）。
11. **安卓 App 改成通讯录模式**（默认）：好友列表、「邀请好友」显示二维码和可复制的邀请码、「加好友」从剪贴板读邀请码或打开 `p2pcp://` 链接（系统相机扫出来的链接能直接跳进 App）、选好友发送；后台接收改成前台服务（常驻通知），可以关。App 里先不做扫码（要摄像头 + 解码库）。
12. **二维码在 Go 里生成**：引入 `rsc.io/qr`（小、BSD 许可），`p2pcp invite -qr <png>` 出图，安卓和网页都直接显示这张图。（默认）
13. **发布：GitHub Releases**（仓库本来就是公开的）：安卓 APK 换成固定的发布签名（密钥只放本机并备份，不进仓库；现在每台机器各用自己的 debug 签名，朋友装了以后没法覆盖升级）、Windows zip、macOS zip、Linux tar + install.sh。App 和桌面版启动时查一次最新版本，有新版就提示。（默认）
14. **协议兼容**：传文件仍是 ALPN `p2pcp/2`，旧版之间照常能传；新增的只有 `p2pcp-pair/1` 和本地文件格式。（默认）

## 待定

- **macOS 的 Gatekeeper / Windows 的 SmartScreen**：没有签名的程序第一次打开会被拦。倾向不花钱买证书，在给朋友的说明里写清「右键 → 打开」（macOS）/「仍要运行」（Windows）。
- **Windows / macOS 实机测试**：本机只有 Linux。倾向先交叉编译 + wine 冒烟，实机找朋友或借一台测。
- **安卓后台接收的耗电**：前台服务每个好友房间都要定期注册（现在 5 秒一次）。倾向后台改成 25 秒一次（NAT 映射最短 60 秒），实测一天的耗电再定默认开不开。
- **好友多了以后的常驻接收**：见决策 7。
- **公司网络封 UDP 时走 TCP 443 中继**：朋友的 Windows 笔记本更可能遇到。倾向放在最后一步，先看朋友实际用起来有没有碰到。
- **99-server 的 3M 出方向**：几个人同时走中继会互相挤。倾向先不管，后台升级会把能直连的都切走。

## 明确不做（这次）

iPhone、一对多 / 群发、账号和中心化的好友目录、网页版（浏览器里直接传）、App 内扫码、安全码核对（防邀请码泄露）。
