# 设计：P2P 直传给朋友用（通讯录模式 + 四平台客户端）

图：[27-flow-pairing](27-flow-pairing.mmd)（加好友）、[34-contacts](34-contacts.mmd)（通讯录和各端客户端），总览里的 `contacts`、`desk` 节点。
上一份设计（先体检、再直传，已完成）归档在 [designs/2026-11-21-preflight.md](designs/2026-11-21-preflight.md)。

## 目标

把 p2pcp 从「我自己的一台手机 ↔ 一台电脑」做成**我和朋友都能直接用的传文件工具**：朋友装上就能用，不用懂打洞、不用配服务器；
加好友扫一次码（或者微信发一段邀请码），之后选人就能发，对方自动收。能直连就直连，打不通走 99-server 中继，并在后台升级回直连（上一份设计已做好）。

## 决策

1. **平台：安卓、Windows、macOS、Linux，不做 iPhone。**（用户定，2026-11-21）iOS 不能侧载，要 99 美元/年的开发者账号走 TestFlight，后台常驻接收也受限。
2. **通讯录模式代替「打包时写死的房间密钥」。**（默认）每台设备第一次运行生成设备密钥（X25519，Go 标准库 `crypto/ecdh`）和设备名；每一对好友的房间密钥 = `HKDF(ECDH(我的私钥, 对方公钥), "p2pcp pair")`，两边算出来一样，线路上不出现。会合服务器、打洞、QUIC 认证都不用改：配对密钥直接当现在的「房间密钥」用。我自己的电脑和手机也只是通讯录里的两个联系人，旧的 `room` 文件和 `.pc` / `.phone` 两个房间退役（自己的设备重新加一次好友，不做迁移）。
3. **加好友 = 一次性邀请码，扫一次两边就互相加上。**（默认）邀请码 = 会合地址 + 128 位一次性密钥，写成 `p2pcp://join/<base32>`，可以当文字发微信，也可以显示成二维码当面扫。被邀请方用这个密钥当房间密钥，和邀请方会合、打洞、QUIC 认证（现有流程），然后在 ALPN `p2pcp-pair/1` 上互换名片（设备名 + 公钥），各自算出配对密钥、写进通讯录，邀请码作废。128 位是因为会合服务器看得到房间号（密钥的 HMAC），密钥短了能被离线穷举。
4. **邀请码 24 小时有效，由邀请方的常驻接收在后台等。**（默认）微信发过去，朋友可能过几个小时才点；不要求两边同时开着界面。用过一次或过期就删。
5. **会合地址跟着邀请码走，存进每个联系人。**（默认）朋友零配置；以后不同的朋友圈子可以用不同的服务器。默认都是 99-server（会合 7001 / 7000，中继 3478，出方向 3M 大家共用）。
6. **好友发来的文件自动接收，按好友分目录**（`下载/P2P直传/<好友名>/`），弹通知。（默认）只有通讯录里的人进得了配对房间，不再逐个确认。
7. **常驻接收 `serve` 同时听所有好友的房间和没用掉的邀请**：每个房间一个 socket，以 `recv` 身份注册（现有 `keepServing`）。（默认）几十个好友以内没问题；再多就要改成「一个收件房间 + 连上后再认人」，先不做（待定）。
8. **核心逻辑都放在 Go 的 p2pcp 里，各端界面只是薄壳。**（默认）新命令：`p2pcp id`（看 / 改设备名）、`invite`（出邀请码）、`join <码>`、`contacts`（列出 / 删除）、`send -to <好友> 文件…`、`serve`。界面照现在的方式启动它、读 `-progress` 的 `@` 行。四个平台共用一份实现。
9. **桌面版（Windows / macOS / Linux）是一个本地网页界面：`p2pcp app`。**（默认）同一个进程里跑 `serve`，加一个只听 `127.0.0.1` 的小 HTTP 服务（HTML 内嵌进二进制），自动打开浏览器：通讯录、加好友（显示二维码 / 粘贴邀请码）、选文件发送、收发记录。纯 Go、`CGO_ENABLED=0`，一条命令交叉编译出三个平台；不用 Fyne / Wails 这类要 cgo 的 GUI 库。网页里选的文件要先经本机 HTTP 传给 p2pcp（和安卓 App 先复制到缓存一样），大文件主要靠右键发送。
10. **桌面系统集成按平台各做一份**（默认）：开机自启（Windows 启动文件夹快捷方式 / macOS `~/Library/LaunchAgents` / Linux systemd 用户服务）；右键发送（Windows「发送到」文件夹 / Linux Dolphin 菜单，macOS 先不做、用网页选文件）；通知（Windows PowerShell toast / macOS `osascript` / Linux `notify-send`）。
11. **安卓 App 改成通讯录模式**（默认）：好友列表、「邀请好友」显示二维码和可复制的邀请码、「加好友」从剪贴板读邀请码或打开 `p2pcp://` 链接（系统相机扫出来的链接能直接跳进 App）、选好友发送；后台接收改成前台服务（常驻通知），可以关。App 里先不做扫码（要摄像头 + 解码库）。
12. **二维码在 Go 里生成**：引入 `rsc.io/qr`（小、BSD 许可），`p2pcp invite -qr <png>` 出图，安卓和网页都直接显示这张图。（默认）
13. **发布：GitHub Releases**（仓库本来就是公开的）：安卓 APK 换成固定的发布签名（密钥只放本机并备份，不进仓库；现在每台机器各用自己的 debug 签名，朋友装了以后没法覆盖升级）、Windows zip、macOS zip、Linux tar + install.sh。App 和桌面版启动时查一次最新版本，有新版就提示。（默认）
14. **协议兼容**：传文件仍是 ALPN `p2pcp/2`，旧版之间照常能传；新增的只有 `p2pcp-pair/1` 和本地文件格式。（默认）
15. **收件房间按方向分（第 1 步冒烟测试抓到）**：最初两个方向共用一个配对房间，结果自己的 `send -to 好友` 和自己的 `serve` 在同一个房间里，会合服务器把它们配成一对，文件发给了自己（旧版两个方向各用 `.pc` / `.phone` 房间，所以没这个问题）。改成发给 X 的房间密钥 = `HMAC(配对密钥, "p2pcp inbox" ‖ X 的公钥)`（`inboxSecret`），每台设备的 `serve` 只听「发给自己」的那个；`check -to` 两端跑同一条命令，仍用不分方向的配对密钥。
16. **邀请码只能用一次的顺序**：被邀请方先发名片；邀请方在通讯录的锁里把邀请作废、把对方加进去，成功了才回自己的名片，否则回拒绝原因。同一个码被两个人同时用，后到的那个拿不到名片、加不上。回完名片要等对方先关连接（最多 3 秒），否则还在路上的名片会被丢掉（冒烟测试抓到的 `Application error 0x0`）。
17. **`join` 默认只等 20 秒**：邀请方在线时 1 秒内就配上；邀请码用过 / 过期后，邀请方的 `serve` 不再听那个房间，原来的 60 秒会让朋友干等 1 分钟（netns sym ↔ sym 抓到）。
18. **`serve` 的实现**：每 2 秒看一次 `contacts.json` 的修改时间，按「公钥 + 会合地址 + 名字」决定多听 / 少听哪些房间（改名、换服务器会重开）；每个房间一个 `keepServing`，它现在能被 `o.quit` 叫停、`waiting` 为空时不刷状态。身份和通讯录读改写用跨平台的 `lockFile`（Unix 用 flock，Windows 用独占创建锁文件），画像缓存也换成了它，为第 5 步编 Windows 做准备（现在 Windows 还卡在 `syscall.Kill`）。
19. **国产安卓熄屏会冻结 App（第 2 步真实测出来的）**：vivo（OriginOS）熄屏几十秒后把 App 主进程和 p2pcp 子进程都放进 `freezer:/frozen`，前台服务、标准的「忽略电池优化」、`RUN_ANY_IN_BACKGROUND` 都挡不住，熄屏后就收不到（发送端 60 秒等不到注册）。只有用户在系统设置里给 App 打开「允许后台高耗电」才行（App 做不到，adb 也改不了）。产品上：App 启动时申请标准的忽略电池优化（别的品牌靠它）；接收卡片下面一行蓝字，点了跳到本 App 的系统设置页；发送端对方不在线时的报错改成说人话（「对方的 P2P 直传没开着，或者手机熄屏后被系统冻结了」）。打开之后实测熄屏 90 秒仍然秒收（5G，4MB）。给朋友的上手说明里要写这一步（第 7 步）。
20. **安卓后台接收**：前台服务 `P2PService`（`dataSync` 类型）常驻 `serve -reg 20s`：会合服务器只给 30 秒内注册过的配对，NAT 映射最短 60 秒，所以 20 秒；好友来发时最多晚一个间隔配上。换网时杀掉 serve、2 秒后用新的 `-lan` 重启；收完的文件挪进「下载/P2P直传/<好友名>/」并发通知，加上新好友也发通知。设备名默认取系统的「设备名称」，没有就用型号（这台 vivo 取到的是 `V2238A`），点本机名可改。
21. **电脑端 `p2p-direct`**：常驻改成 `serve`（旧的 `daemon` 参数保留成别名），发送时只有一个好友就直接发、多个就 zenity 弹框选；`invite` 把邀请码复制到剪贴板（wl-copy）并打开二维码图片；`join`、`contacts` 直接转给 p2pcp。`install.sh` 不再生成 `room`，APK 也不再写房间密钥，只写会合地址。

22. **诊断数据自动上报，默认开、可以关。**（用户定，2026-11-21）每次连接结束（成功、走中继、失败都算），把那条结果记录发给会合服务器：两端 NAT 画像（含映射到的公网地址）、预测、实际结果、原因码、各段耗时、第几轮、是否升级到直连、p2pcp 版本、系统类型。**不含**文件名、好友名、任何密钥；设备用设备 ID 的哈希区分。走现有的 UDP 会合端口（新报文 `/H <json>`，一个包装得下），会合服务器追加进一个 jsonl；发不出去就存在本机队列里，下次连接时补发（最多攒 100 条）。关掉：App 里一个开关、桌面版设置、命令行 `-upload off`，存在 `settings.json`。App 第一次打开时用一句话说清传了什么。只在熟人之间用，带公网 IP 可以接受。**存放**：服务器上 `/var/lib/uu-rendezvous/reports.jsonl`（systemd `StateDirectory`，超过上限就滚动）；分析时拉到本机不进 git 的 `lab/real/reports/`（加进 `.gitignore`）。**原始记录有朋友的公网 IP，不能进公开仓库**，仓库和文章里只放汇总表或打码的样例。上报端口谁都能发，靠现有的按 IP 限速，先不做认证。本机的完整记录（`history.jsonl`、`trace/`、日志、崩溃现场、待发队列）都在缓存目录，只经诊断报告由用户自己发出。
23. **失败原因分类成固定的原因码，每类配一句人话和一个能做的动作**（默认）：`rdv_unreachable`（本机连不上会合服务器：断网、UDP 被封、端口被拦）、`peer_offline`（对方没在线：App 没开、手机熄屏被冻结）、`punch_blocked`（两边都在线但打不通，附上两端 NAT 类型；有中继就自动走中继，不算失败）、`relay_failed`（中继也不通）、`conn_lost`（传到一半断了，会自动续传）、`auth_failed`（对方不是这个好友，房间号撞了或者有人冒充）、`local_error`（读不了文件、磁盘满等）。界面上显示这句人话和「查看详情」，`history.jsonl`、上报、`@CHECK` 里带原因码。连接过程中（还没失败）也报当前卡在哪一层，比如「正在等对方上线」「正在打洞（第 2 轮）」「打不通，改走中继」。
24. **每次连接的完整过程记在本机**（默认）：每一轮的本机 / 对方候选、映射地址、收到了哪些包（来源、类型）、各段时间点、最后的原因码，写进 `~/.cache/p2pcp/trace/`，每次连接一个文件，保留最近 50 次、总共不超过 5MB。不自动上报（太细），只进诊断报告。
25. **「生成诊断报告」**（默认）：`p2pcp report` 打包本机 NAT 画像（现测一次）、单端体检结果、最近 50 条连接记录、最近 10 次连接过程、最近的日志、版本和系统信息，出一个文本文件（几十 KB，微信能直接发）。安卓 App、桌面版各一个按钮，生成后直接调起分享。好友名和文件名替换成代号。
26. **日志落盘、崩溃留现场**（默认）：安卓 App 现在的日志只在界面上显示 14 行、关掉就没了，改成 p2pcp 的日志滚动写进缓存目录（最多 2MB）；Go 主流程和每个连接的 goroutine 加 `recover`，panic 时把栈写进 `crash-<时间>.txt`，下次启动时提示、并放进诊断报告。
27. **服务器那边的统计**（默认）：会合服务器本来就看得到配对次数、中继次数和时长，再加上客户端在注册标志里报的版本（`v=…`）。`lab/real/report-stats.py` 汇总上报的记录：按 NAT 组合看成功率和预测准确率、原因码分布、中继占比和升级成功率、建连耗时分布、各版本占比。这是改进方向的依据，也是文章素材。
28. **原因码怎么落地（第 3 步实现时定的）**：`reason.go` 按哨兵错误归类（`errNoPeer`、`errPunchTimeout`、`errRelay`、`errAuth`、`interrupted` 等），握手失败这类没有哨兵的用 `withReason` 直接标。机器行在 `@ERROR` 前多一行 `@REASON <码> <人话>。<动作>`，旧版 App 不认识、忽略。对方验不过本端证明时，本端看到的只是读失败（对方以 0x50 关连接），也归成 `auth_failed`。`connect` 的所有失败都记一条（以前只有打洞超时才记），只有两种不记：主动叫停的，和常驻接收空等时连不上会合服务器（没人在用，记下来全是噪音）。连上之后出的错（断线、握手 / 认证失败）也记，结果行里写「之后出错」和原因码。阶段提示（「正在等对方上线」等 1.5 秒还没人才报、「正在打洞（第 N 轮）」第 2 轮起才报、「打不通，改走中继」）只给发送端：常驻接收同时听很多房间，各报各的会刷屏。`-stun off`（测试用）仍然不体检、不记录、不上报。
29. **崩溃现场用 `debug.SetCrashOutput`**：每个进程启动时把 Go 运行时的崩溃输出接到 `crash.txt`，任何 goroutine 的 panic、fatal error 都能留下来，比逐个加 `recover` 全；下次启动发现它不是空的就改名成 `crash-<时间>.txt`（`@CRASH`）。只在常驻接收每个连接的 goroutine（`keepServing`）里另加 `recover`：一个连接出的问题不该带走整个常驻接收。
30. **上报的细节**：服务器收到 `/H` 回 `/HK <sha256 前 8 位>`，没回执才进本机队列（最多 100 条），新的这条先发、一次最多补发 20 条（服务器按 IP 限速每秒 20 个包）；上次失败后 5 分钟内不再试，直接进队列，免得服务器是旧版、本机断网时每次连接结束都多等一秒多。`err` 文字可能带好友名，只在原因码是 `unknown` 时带上、并且打码。两端各报一条，带同一个连接号 `conn`（两端会合 id 排序后的哈希）和对方版本（会合标志里新加的 `v=`），统计时按连接去重、能对上两端。设备哈希只在有通讯录身份时带，`-room` 模式不为上报去生成身份。服务器 `-reports` 每行包成 `{rx, from, r}`，超过 100MB 滚动成 `.1`。
31. **诊断报告打码靠登记**：`send` 一开始（在检查文件之前，出错的日志里也有文件名）、接收时一拿到文件名、加好友 / 解析好友时，把文件名、完整路径、好友名追加进缓存目录的 `names.txt`；`p2pcp report` 读它和通讯录，长的先换：本机设备名 →「本机」、好友 →「好友N」、文件 →「<文件N.扩展名>」（完整路径和文件名对到同一个代号）。少于 2 个字的名字不打码（会误伤正文）。本机体检另起一个子进程跑 `p2pcp check`，收下它的输出。
32. **安卓的诊断报告存进「下载/P2P直传」再分享**：没有 Gradle 就没有 androidx 的 FileProvider，MediaStore 的 Uri 可以直接带读权限分享，用户也能在文件管理器里找到。另外 App 启动 p2pcp 时传 `TZ`（Go 在安卓上不认系统时区，默认 UTC），p2pcp 嵌入 `time/tzdata`（约 450KB），日志和报告里的时间和电脑那边对得上。

33. **传输中可以手动取消，两边都有按钮。**（用户定，2026-11-24：真机上发 2.5GB 时停不下来）「取消」和「中断」分开：中断（断网、换网、Ctrl-C、进程被杀）照旧重连续传、留半成品；取消是用户点的按钮，两边都停、发送端不重连、接收端**删掉半成品**（用户没选 A/B，先按「删掉」做，要改成留着续传只动 `recvFile` 里的一个 defer）。界面上取消不算失败：灰字「已取消 / 对方取消了」，不弹红色失败、不带原因码动作。
34. **怎么让对方知道：QUIC 应用错误码 `0x43`（`codeCanceled`）关掉这个会话的所有连接。**（默认）对方在任何一个流操作上都会拿到 Remote 的 `ApplicationError`，不用在控制流上加消息、也不用对方正好在读控制流。旧版对端看到的是普通断开（当成中断），新版之间才认得出。机器行加 `@CANCELED me|peer <文字>`；history / 上报记成 `canceled` / `peer_canceled`。
35. **接收端取消时 CONNECTION_CLOSE 可能丢：靠发送号兜底。**（默认）每次 `send` 随机一个发送号（offer 的 `sid`，重连续传时不变）；接收端取消时记下它（10 分钟），发送端当成中断重连过来、拿同一个发送号 offer，就回 `{"t":"cancel"}` 并用 `codeCanceled` 关连接（光回消息不够：紧接着关连接，没发出的流数据会丢——netns 抓到的）。重新发同一个文件是新的发送号，照收。发送端取消时丢了包没关系：接收端 15 秒空闲超时后当成中断，半成品一周后清掉。
36. **谁来叫取消**（默认）：`cancel.go` 里有一张正在进行的传输表（发送一次 `send` 一项，接收一个好友的一次会话一项，升级到直连后还是同一项）。桌面版网页在同一进程里调 `/api/cancel`（`{"ch":"send:N"}` 或 `{"ch":"recv"}`）；手机 App 往 p2pcp 的 stdin 写一行 `cancel` / `cancel recv`（带 `-progress` 时才读 stdin，systemd 给的 `/dev/null` 读到头就不读了）。接收端的取消先只做「取消正在收的（所有好友的）」：界面上本来就只显示一个接收进度，按好友分开等好友多了再说。网页上文件还在交给 p2pcp（上传到临时目录）时取消就是中止上传；App 还在复制到缓存时取消就停止复制。

37. **Windows 版就是一个 `P2P直传.exe`，双击自己装好。**（默认，第 5 步）`-H windowsgui` 编译（没有黑框），不带参数运行 = `launch`：不在安装目录里就复制到 `%LOCALAPPDATA%\Programs\P2P直传\`，经 PowerShell（`WScript.Shell`）建开机自启（启动文件夹，`app -no-browser`）、开始菜单（`app`）、「发送到」（`sendto`）三个快捷方式，在 HKCU 的 `Uninstall\P2PDirect` 登记卸载（「应用和功能」里能卸）、登记通知用的 AppUserModelID，然后从安装目录启动 `app`。都写在当前用户下，**不要管理员权限、不做安装包**。再双击：exe 内容一样就只补快捷方式、不打断正在跑的；不一样（新版）先 `POST /api/quit` 让旧版退出，再覆盖（文件锁住时重试 5 秒）。`uninstall` 删快捷方式、登记和安装目录（自己正在跑，交给一个隐藏的 `cmd` 等 2 秒再删），设备密钥、好友、收到的文件留着。`app` 没给 `-o` 时收到「下载\P2P直传」（Windows 取 Downloads 这个已知文件夹，被挪过也对），Windows 上默认弹通知。exe 本身的图标先不做（要 windres 或第三方工具），快捷方式和「应用和功能」用安装时写出的 `.ico`（PNG 直接塞进 ICO）。
38. **右键「发送到」：`p2pcp sendto 文件…` 把路径交给正在跑的 app，在网页上选发给谁。**（默认）不另做选好友的窗口（Windows 上没有 zenity），也不复制文件（网页选的文件要先经 HTTP 传一遍，大文件慢）：`sendto` 读 `app.json` 里的令牌，`POST /api/pick`（带 cookie 和 Origin，和网页过同一个 guard），app 没在跑就先在后台拉起来（最多等 15 秒）；然后打开网页，顶上一张「要发送的文件」卡片，好友按钮变成「发给他」，点了走 `/api/send` 的 JSON 分支，直接从原处发、发完不删原文件。路径只留在服务端，网页只拿到编号和文件名；一小时没选就作废，可以点「不发了」。进度、取消、记录和别的发送一样。Linux 的 Dolphin 右键以后也可以改走这条路（现在还是 `p2p-direct send` + zenity）。
39. **Windows 通知用 PowerShell 弹 toast，只弹结果。**（默认）每弹一次要起一个 PowerShell（半秒多），所以只弹完成、失败、取消、加上好友，不弹进度（Linux 的 `notify-send` 照旧原地更新进度）。用安装时登记的 AppUserModelID，通知上显示「P2P 直传」；没装过就借 PowerShell 的。点通知打开网页（带令牌的地址：令牌只防别的网站，本机的程序本来就读得到 `app.json`）。
40. **Windows 防火墙不加规则，只提示。**（默认）加放行规则要管理员。第一次绑 UDP 时 Windows 会弹「安全中心警报」，网页顶上一次性提示「点允许」，使用说明里也写。点了取消多半也能用：打洞是两边先往外发，出方向建立的 UDP 流的回包是放行的（**待实机确认**）。
41. **收文件在 Windows 上的两处不同**（第 5 步 wine 测出 / 读代码发现）：① 文件名先换掉不能用的字符再取文件名：`\/:*?"<>|` 换成全角（`：`），结尾的点和空格去掉，`CON`、`NUL`、`COM1` 这类设备名前面加 `_`；先换再取，`w:x.bin` 才不会被 `filepath.Base` 当成盘符截成 `x.bin`。Linux、安卓不动（冒号在那边是合法的）。② 收齐后先关文件再改名：Windows 上开着的文件改不了名。
42. **打包：`apps/win/build.sh` 出 `P2P直传-windows-amd64-<版本>.zip`（exe + 使用说明，约 5MB）。**（默认）纯 Go 交叉编译，本机不用装别的；会合地址用 `-ldflags -X main.defaultServer=…` 写进 exe（朋友没有 `install.sh` 写的配置文件，邀请好友时要用），取自 `~/.config/p2pcp/server`。`serverConf` 改成读各系统的用户配置目录（Windows 是 `%AppData%\p2pcp\server`），都没有再用写进去的默认值。zip 里的中文文件名打 UTF-8 标志，资源管理器不乱码。
43. **Windows 上界面装进 WebView2 窗口，不开浏览器标签页。**（用户定，2026-11-24：「网页还是差点意思」）Win10 / 11 自带 WebView2（Edge 内核），窗口有自己的标题「P2P 直传」和图标、没有地址栏，里面还是同一个网页。Go 绑定在五个方案里选了 `github.com/wailsapp/go-webview2`（Wails 维护的分支，用的人最多；自己写 COM 绑定最干净但工作量大，Edge `--app` 模式控制不了窗口，整个换 Wails 框架会丢掉纯 Go 交叉编译）。引入前审过 v1.0.23：模块哈希和 sum.golang.org 一致；不联网、不执行程序、不写文件和注册表（注册表只读、找系统装的 WebView2）；只加载系统 DLL 和 WebView2 运行时自己的 DLL；库里带的 `WebView2Loader.dll` 和 `go-winloader` 只在 `native_webview2loader` 标签下才编进来，默认用纯 Go 重写的加载器（`go version -m` 核对过 exe 里没有）；它还会清掉 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 这类能注入参数的环境变量。窗口是单独的进程（`p2pcp window <地址>`）：后台 app 不碰消息循环，关窗口不影响收文件；库初始化失败会直接 `os.Exit`，放在单独的进程里也只关掉窗口，退出前先退回浏览器打开。已经开着窗口时（按窗口类名找）再打开只把它提到前面，起窗口前 `AllowSetForegroundWindow` 让它能跳到最前。WebView2 的浏览数据放缓存目录。以后可以用 WebView2 拿到拖进窗口的文件的真实路径，拖文件也从原处发、不用经 HTTP 传一遍（先不做）。macOS / Linux 仍开浏览器。
44. **能退出、能关开机自启。**（用户提的：「这个东西能关掉吗」）网页「设置」里：「退出 P2P 直传」（先确认，正在传时多一句会中断；退出后显示「下次从开始菜单 / 启动器打开」，WebView2 窗口里窗口跟着关）；「开机自动启动」开关（Windows = 「启动」文件夹里的快捷方式，Linux = `systemctl --user enable/disable p2p-direct`；没装 systemd 服务时不显示）。关掉窗口 / 标签页只是关界面，后台照样收，界面上写明。Linux 的 systemd 单元改成 `Restart=on-failure`：点「退出」正常退出时不会被拉起来，崩溃、被杀仍自动重启。

## 待定

- **macOS 的 Gatekeeper / Windows 的 SmartScreen**：没有签名的程序第一次打开会被拦。倾向不花钱买证书，在给朋友的说明里写清「右键 → 打开」（macOS）/「仍要运行」（Windows）。

- **公司网络封 UDP 时走 TCP 443 中继**：朋友的 Windows 笔记本更可能遇到。倾向放在最后一步，先看朋友实际用起来有没有碰到。
