## 0. 当前进度与交接

### 0.1 核心结论
1. **UU 远程底层是 WebRTC 体系（ICE/STUN/TURN）**：P2P 优先，约 12 秒打不通就回退到 UU 加速器节点上的 TURN 中继（开源逆向项目 uulink 已证实）。

4. **学习主线（用户定的方向）**：打洞原理 + 良好的网络传输；中继只作为备用兜底，不作为重点。

## 01 · 网易 UU 远程是怎么做到"免费又像在家里"的

> 证据等级：**[确认]** = 有开源逆向/官方资料佐证；**[推断]** = 根据行业惯例和间接证据推出，待实测验证（见 03）。

### 1. 已知事实

| 项 | 内容 | 等级 | 来源 |
|---|---|---|---|
| 前身 | 原名 GameViewer 远程，2024-12-10 更名 UU 远程；Windows 进程仍叫 `GameViewer.exe` / `GameViewerServer.exe` / `GameViewerHealthd.exe` | 确认 | 百度百科 / uu-remote-ubuntu-bridge |
| 规格 | 最高 4K 144Hz、HDR、4:4:4 真彩、码率上限可设到 500Mbps、"超级屏"虚拟显示器 | 确认 | 官方 / App Store |

| 传输栈 | **WebRTC 体系：ICE + STUN + TURN**。uulink 的参数有 `-transport auto|relay`、`-p2p-timeout 12s 后改走 TURN`；信令可下发 `server_requires_relay=true` 强制中继 | 确认 | uulink README |

### 2. 架构还原

```
           ┌──────────── 信令/账号 (HTTPS + WSS?, protobuf) ────────────┐
           │  登录(JWT) · 设备列表 · 房间/分享码 · 交换 SDP/ICE 候选      │
           │  · 决定是否强制中继 · 下发 STUN/TURN 服务器列表              │
           └───────▲───────────────────────────────────────▲────────────┘
                   │                                       │
   被控端 GameViewerServer.exe                      控制端 GameViewer.exe / App
   采集(DXGI/WGC) → 硬件编码(NVENC/AMF/QSV)          硬件解码 → 渲染 → 输入回传
                   │                                       │
                   ├──────── ① P2P 直连 (UDP 打洞，~90%+) ──┤
                   │                                       │
                   └── ② TURN 中继 (UU 加速器节点，兜底) ────┘
```

一次连接的时序（标准 ICE 流程，UU 应基本相同）：

1. 双方各自向 STUN 服务器问"我在公网上是谁"→ 得到 **srflx 候选**（公网 IP:端口）；同时收集本机网卡地址（**host 候选**）、向 TURN 申请中继地址（**relay 候选**）。
2. 经信令服务器交换候选列表。
3. 双方**同时**向对方所有候选发 STUN Binding 连通性检查——这一步就是"打洞"：自己往外发的包在本方 NAT 上打开映射，对方的包就能进来。
4. 选出最优可用路径（host > srflx > relay）。12 秒左右还没通就用 relay。
5. DTLS 握手协商密钥 → SRTP 传音视频，SCTP DataChannel 传键鼠/剪贴板/文件。**[推断]** 也可能把 WebRTC 只当连通层，媒体用自研 "UDP+" 协议跑在同一条 5 元组上。

### 3. 为什么免费还能这么快——真正的原因

#### 3.1 经济学：P2P 让网易几乎不用付视频带宽
远控最贵的成本是**中转带宽**。国内 BGP 带宽按 Mbps 计价很贵；一路 4K144 流 30~100Mbps，如果都走服务器，免费根本撑不住。ToDesk/向日葵免费版慢，本质是**走中转时被限速**。
UU 的做法：
- 90%+ 会话打洞成功走 P2P → 视频流量走的是**你自家的上行带宽**，网易只承担信令（KB 级）。
- 剩下的走中继，用的是 **UU 加速器原有的节点网络**——基础设施已经存在、边际成本低。**[推断]** 加速器的高峰在晚上游戏时段，远程办公的高峰在白天，两者错峰。
- 因为不花钱，所以才敢把码率上限放到 500Mbps——**"像在家里"的画质主要来自"敢给码率"**。

#### 3.2 打洞成功率高：游戏加速器的老本行
加速器公司长期和国内各运营商的 NAT 行为、UDP QoS 打交道，积累了：
- 多台 STUN 探测 NAT 类型；对称 NAT 做**端口预测 / 端口喷洒**（见 02 §4）。
- 大量真实网络的端口分配规律统计（运营商、地区、光猫型号）。
- 节点就近选择、跨运营商（电信↔移动）的优化线路——中继也不慢。

#### 3.3 低延迟管线：云游戏/串流的技术路线
端到端延迟 = 采集 + 编码 + 网络单程 + 抖动缓冲 + 解码 + 显示

| 环节 | 典型做法 | 耗时 |
|---|---|---|
| 采集 | DXGI Desktop Duplication / Windows.Graphics.Capture，GPU 纹理零拷贝 | 1~3 ms |
| 编码 | NVENC/AMF/QSV 低延迟预设、无 B 帧、帧内刷新(intra-refresh)代替大 I 帧、切片 | 2~5 ms |
| 网络 | P2P 直连同城 5~20 ms；UDP、不等重传 | 变量 |
| 抗丢包 | NACK 选择重传 + FEC 前向纠错，按丢包率动态调整冗余 | — |
| 拥塞控制 | 类 GCC/BBR 的带宽估计，网络变差先降码率/分辨率而不是卡顿 | — |
| 抖动缓冲 | 尽量小（远控宁可偶尔花屏也不要累积延迟） | 0~10 ms |
| 解码显示 | 硬解 + 144Hz 下一帧仅 6.9 ms | 1 帧 |

用的是 **UDP + 自己控制重传**：TCP 的队头阻塞会让一个丢包卡住后面所有帧，这是基于 TCP 的远控"拖泥带水"的根本原因。

#### 3.4 商业动机 [推断]
导流到 UU 加速器 / 网易游戏生态、积累用户、以高级功能会员变现。免费不是做慈善，而是 P2P 架构让免费的边际成本接近 0。

### 4. 对自研的启示（一句话版）

> **P2P 打洞成功率决定了你的成本，UDP 传输 + 硬件编解码决定了你的体验，中继只是保底。**

## 02 · NAT 穿透（打洞）原理

### 1. 问题本质

家里的电脑没有公网 IP，路由器（以及运营商的 CGNAT）做了地址转换。外面的人**主动**发进来的包，NAT 不知道该给谁，直接丢弃。
打洞的核心思想只有一句话：**让双方同时往外发包，各自在自己的 NAT 上"开门"，让对方的包看起来像"回复"。**

### 2. NAT 行为分类（RFC 4787，比老的 NAT1~4 更准确）

要分开看两个维度：

**映射行为（Mapping）**：同一个内网 `IP:端口` 发往不同目的地时，公网端口变不变？
- **EIM 端点无关映射**：不变 → 对端能用 STUN 查到的端口连进来 ✅
- **EDM/ADM 端点相关映射**（俗称"对称型 NAT4"）：每个目的地换一个端口 → STUN 看到的端口对对端没用 ❌

**过滤行为（Filtering）**：谁能往这个映射里发包？
- EIF 任何人都能发（全锥 NAT1）
- ADF 我发过的 IP 才能回（限制锥 NAT2）
- APDF 我发过的 IP:端口 才能回（端口限制锥 NAT3）

| 本端 \ 对端 | NAT1 | NAT2 | NAT3 | NAT4 对称 |
|---|---|---|---|---|
| NAT1 | ✅ | ✅ | ✅ | ✅ |
| NAT2 | ✅ | ✅ | ✅ | ✅ |
| NAT3 | ✅ | ✅ | ✅ | ⚠ 端口预测 |
| NAT4 | ✅ | ✅ | ⚠ 端口预测/喷洒 | ❌ 基本只能中继 |

你的网络实测（`lab/stunprobe`，2026-10-16）：中国移动公网 `183.197.x.x`，**EIM**，四台 STUN 映射同一端口 → 属于 NAT1~3，和绝大多数对端都能直连。

### 3. 标准流程：STUN / TURN / ICE

- **STUN**（RFC 8489）：一个 20 字节头的 UDP 请求，服务器把"它看到的源地址"放进 `XOR-MAPPED-ADDRESS` 回给你。`lab/stunprobe/main.go` 用不到 150 行手写了它。
- **TURN**（RFC 8656）：中继。你在服务器上申请一个公网端口，所有数据经它转发。永远能通，但费带宽。开源实现 `coturn`。
- **ICE**（RFC 8445）：把 host / srflx / relay 候选两两配对、按优先级做连通性检查、选最优路径。WebRTC 就是 ICE + DTLS + SRTP/SCTP。

### 4. 对付对称 NAT 的技巧

1. **端口预测**：很多 NAT 按顺序分配端口（+1、+2）。先连两台 STUN 看增量，猜下一次的端口。
2. **端口喷洒 / 生日攻击**（Tailscale 用的）：对称端开 256 个 socket，锥形端向对方公网 IP 的随机端口发约 1000 个包——由生日悖论，命中概率很高。`lab/punch -spray N` 是最简化的版本。
3. **UPnP-IGD / NAT-PMP / PCP**：让路由器主动开端口映射（很多家用路由器支持，但 CGNAT 后没用）。
4. **IPv6**：国内宽带和 4G/5G 普遍有全球单播 IPv6，没有 NAT，只有状态防火墙——双方同时发包即可打通，成功率极高。**自研时务必把 IPv6 候选放在最高优先级。**
5. **TCP 打洞**（同时 SYN）：成功率远低于 UDP，只作为 UDP 被 QoS 时的备选。

### 5. 国内网络的特殊情况

- **CGNAT**：运营商给你 `100.64.0.0/10` 地址，外面还有一层 NAT，通常是对称型。可打电话要公网 IP（电信最容易）。
- **光猫路由模式 + 自家路由器 = 双层 NAT**：改光猫桥接、路由器拨号，常能直接变 NAT1。
- **运营商 UDP QoS**：大流量 UDP 可能被限速或丢包，晚高峰明显——这是 FEC 与码率自适应要解决的问题。
- **NAT 映射超时**：UDP 映射常在 30 秒~5 分钟内过期，必须**每 15~25 秒发保活包**（`lab/punch` 里的 `KA`）。
- **本机多网卡 / TUN 代理**：开着 sing-box/Clash TUN 时，"默认出口地址"是虚拟网卡地址（实测本机得到 `172.18.0.1`）。必须像 ICE 一样收集所有网卡地址，并让 P2P 流量绕过代理（不然 STUN 看到的是代理服务器的出口地址）。

### 6. 推荐阅读

- Tailscale《How NAT Traversal Works》 —— 讲打洞讲得最好的一篇文章，必读
- RFC 4787（NAT 行为）、RFC 5780（NAT 行为探测）、RFC 8445（ICE）
- RustDesk 源码 `hbbs`（会合服务器）/ `hbbr`（中继）—— 最接近 UU 的开源远控

## 03 · 怎样亲手验证 UU 远程的行为

目标：把 01 里标 **[推断]** 的内容逐条变成 **[确认]**。抓包结果放到 `../captures/`。
原则：只分析自己设备上的流量，不破解、不改二进制、不滥用网易的中继节点。

### 1. 抓包工具

| 平台 | 工具 | 备注 |
|---|---|---|
| Windows | Wireshark + Npcap；TCPView 看 `GameViewerServer.exe` 开了哪些端口 | 首选 |
| Android | PCAPdroid（免 root，VPN 方式，可导出 pcap）；或者在 APatch root 后用 `tcpdump` | PCAPdroid 走 VPN 会影响 P2P 判断，最好用 tcpdump |
| Linux | `tcpdump -i any -w uu.pcap udp` 抓路由器镜像或在主路由上抓 | — |

### 2. 看什么

**Wireshark 过滤器**：`stun || dtls || rtp || rtcp || classicstun`

| 观察到 | 说明 |
|---|---|
| STUN Binding Request，带 `USERNAME = xxxx:yyyy`、`ICE-CONTROLLING`、`PRIORITY` 属性 | 标准 ICE 连通性检查 ✅ 坐实 WebRTC/ICE |
| 紧接着 DTLS ClientHello | WebRTC 加密握手 |
| 之后大量 UDP 包，Wireshark "Decode As → RTP" 能解析 | SRTP 媒体；否则是自研协议 |
| TURN `Allocate` / `ChannelData`（头两字节 0x40~0x7F） | 走的是中继 |

**判断 P2P 还是中继**：Statistics → Conversations → UDP，按字节数排序。流量最大的那条：
- 对方 IP = 被控端家里的公网 IP（用 `lab/stunprobe` 在被控端查）→ **P2P 直连**
- 对方 IP 属于网易或云厂商机房（查 ip138 / `whois`）→ **中继**

## 05 · 打洞引擎 + 传输协议：实现方案

> 目标：以 P2P 直连为主线，中继只做最后兜底。服务器 `8.140.18.211`（单公网 IP，本机 ping 约 14ms）。
> 核心思路：**服务器只负责"介绍"和"测量"，数据一个字节都不经过它**（兜底中继除外）。

---

### 0. 整体分层

```
┌─────────────────────────────────────────────────────────────┐
│ 应用层   视频 / 音频 / 键鼠 / 剪贴板 / 文件                     │
├─────────────────────────────────────────────────────────────┤
│ 传输层   多通道(优先级) · 序号/ACK/NACK · FEC · 发送节奏控制(Pacer)  │
│          带宽估计(BWE) · 截止时间丢弃 · 加密(Noise/AEAD)          │  ← "良好的网络传输"
├─────────────────────────────────────────────────────────────┤
│ 连通层   候选收集 · 连通性检查 · 选定路径 · 保活 · 断线重连(ICE restart) │  ← "打洞"
├─────────────────────────────────────────────────────────────┤
│ 一个 UDP socket（两层复用同一个 5 元组，按首字节区分报文类型）         │
└─────────────────────────────────────────────────────────────┘
          ▲ 信令 TCP/WS                          ▲ STUN UDP
          └──────────── 8.140.18.211 ────────────┘
```

关键约束：**打洞用哪个 socket，后面的数据就必须用同一个 socket**。NAT 映射绑定在这个本地端口上，换一个端口就等于从头开始。

---

### 1. 服务器的四个角色

| 角色 | 端口 | 作用 |
|---|---|---|
| 信令 | TCP 7000（以后可换 WSS 443） | 设备注册、交换候选、协调同时打洞、下发会话密钥 |
| STUN 主 | UDP 3478 | 返回映射地址 |
| STUN 副 | UDP 3479 | 第二个目的端口：用来测映射行为；支持"换端口回复"，用来测过滤行为 |
| 兜底中继 | UDP 7001 | 只在双方都是随机对称 NAT 时启用，只承载低码率流量 |

**阿里云安全组要放行**：TCP 7000，UDP 3478-3479、7001。

#### 单 IP 能测出什么（RFC 5780 的子集）

| 测试 | 做法 | 能区分 |
|---|---|---|
| 映射 | 同一个本地 socket 分别发给 :3478 和 :3479 | 端口不变 → 锥形（EIM）；端口变了 → **对称**（我们最关心这一项） |
| 过滤 | 请求服务器从 :3479 回复 :3478 收到的请求 | 能收到 → NAT1/2；收不到 → NAT3 |
| 端口分配规律 | 连续开 N 个 socket 或连续发往多个端口，记录映射端口序列 | 顺序递增（可预测）/ 保留原端口 / 随机 |
| **映射存活时间** | 空闲 10/20/40/60/120 秒后，让服务器从原 socket 回包 | 直接算出保活间隔（存活时间 / 2） |

NAT1 和 NAT2 要靠第二个 IP 才能区分。可以给阿里云 ECS 再挂一个 EIP；不挂也行，它对打洞策略几乎没影响。

### 2. 连通层（打洞引擎）

#### 2.1 状态机
```
收集候选 → 交换候选 → 同步开打 → 连通性检查 → 选定路径 → 已连接 ─┬→ 保活/路径监测
   ▲                                                       │
   └──────────────── 网络变化 / 3 秒无包 → 重新打洞 ─────────────┘
```

#### 2.2 候选类型与优先级
| 优先级 | 候选 | 说明 |
|---|---|---|
| 1 | host IPv6（全球单播） | 没有 NAT，只有状态防火墙，同时发包基本必通。**国内最被低估的一条路** |
| 2 | host IPv4 局域网 | 同一局域网时直连；要过滤 docker/TUN 网卡（或者把它们降到最低优先级） |
| 3 | UPnP/NAT-PMP/PCP 映射 | 让路由器主动开端口；CGNAT 后面无效 |
| 4 | srflx（STUN 映射） | 主力 |
| 5 | 预测候选 | 只在对方是对称 NAT 时生成 |
| 6 | relay | 兜底 |

#### 2.3 打洞细节（决定成功率的地方）
1. **同步开打**：服务器先测出到两端的 RTT，再分别通知"在 T+RTT/2 时刻开始"，让两边的第一个包几乎同时出门，缩短"对方的包先到、被本方 NAT 丢掉"的时间窗口。
2. **低 TTL 预热**：先用 TTL=3~5 发几个包。这些包能在本方 NAT 上开出映射，却到不了对方的 NAT，避免某些 NAT 因收到"不请自来"的包而把这个连接拉进黑名单。之后再恢复正常 TTL。Go 里用 `golang.org/x/net/ipv4` 的 `SetTTL`。
3. **检查包要带认证**：事务 ID 加上 HMAC（密钥由信令下发），防止伪造和劫持。回包里带上"我看到你的地址"，这样就能学到 peer-reflexive 候选（`lab/punch` 冒烟测试里已经碰到过这种情况）。
4. **发包节奏**：每对候选间隔 20~50ms 发一次，持续 5~10 秒；成功后立刻停止对其他候选的喷洒。
5. **选定（nomination）**：ID 较小的一方作为控制方，从成功的候选对里选出最优的一对，再发 USE 确认。选定后再观察约 1 秒，如果出现更优的路径（比如发现双方在同一局域网）就升级。

#### 2.4 对称 NAT 策略矩阵
| 本端 \ 对端 | 锥形 | 对称·端口可预测 | 对称·端口随机 |
|---|---|---|---|
| 锥形 | 直接打 | 预测窗口 ±k | **生日攻击**：对称端开 256 个 socket 发往锥形端；锥形端向对称端 IP 的随机端口发 1024 个探测，命中率约 98% |
| 对称·可预测 | 同左 | 双向预测，成功率中等 | 低 |
| 对称·随机 | 生日攻击 | 低 | ❌ → 中继 |

生日攻击的命中率：1-(1-256/65536)^1024 ≈ 98%。代价是瞬间发出上千个包，要限速，不然容易被运营商或路由器的防护拦截。

#### 2.5 保活与迁移
- 保活间隔取实测映射存活时间的一半，通常 15~25 秒；有数据流动时不用额外发保活包。
- 信令的 TCP 长连接是"生命线"，断了就失去重新打洞的能力。
- 网络切换（Wi-Fi ↔ 4G）时：监听网卡变化 → 重新收集候选 → 经信令重新打洞。传输层要能在不重建会话的情况下切换路径（会话用 connection-id 标识，而不是 IP:端口）。

### 3. 传输层（"良好的网络传输"）

远控对传输的要求和下载完全相反：**延迟优先于吞吐，数据有截止时间**。一帧画面 100ms 后才到，就已经没有用了。

#### 3.1 三种路线
| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. QUIC | quic-go 跑在打洞后的 socket 上（它的 `Transport.ReadNonQUICPacket` 正好用来和打洞报文复用一个 socket）；可靠流传控制和文件，DATAGRAM 扩展传视频 | 加密、拥塞控制、多路复用、连接迁移全都现成，很快就能跑通 | 拥塞控制看丢包（Cubic），会把路由器队列塞满，延迟不稳；可调的地方少 |
| B. 自研 | 参考 KCP、WebRTC、SRT，自己写分片/ACK/NACK/FEC/Pacer/BWE | 学得最透；每个参数都能针对远控来调 | 工作量大，坑多 |
| C. KCP | kcp-go 现成实现，自带 FEC | 国内游戏和加速器常用，代码短，适合读 | 拥塞控制偏激进，适合控制流，不适合大码率视频 |

**建议：B 为主，A 作为对照组。** 先用 QUIC 半天跑通端到端作为基准线，再逐个模块自研，并在同样的网络条件下和基准线对比——这是学习效率最高的方式。

#### 3.2 自研协议要素
**包头**（约 16 字节）：`conn_id(4) | type(1) | channel(1) | seq(4) | send_ts_us(4) | flags(2)`，视频包再加上 `frame_id | frag_idx | frag_cnt`。
- 负载不超过约 1200 字节，避免 IP 分片（经过 PPPoE、隧道之后 MTU 会更小）。

**通道与优先级**
| 通道 | 可靠性 | 策略 |
|---|---|---|
| 键鼠输入 | 必达 | 包很小 → 重复发 2 份，RTT 级快速重传，优先级最高 |
| 音频 | 允许少量丢失 | 小 FEC，不重传 |
| 视频 | 截止时间内可靠 | FEC + NACK，超过截止时间就放弃，必要时请求关键帧 |
| 文件 | 可靠 | 后台低优先级，有实时流量时主动让出带宽（LEDBAT 思路） |

**抗丢包**
- **NACK**：P2P 同城 RTT 只有 10~20ms，重传完全赶得上一帧（144fps 时一帧 6.9ms，60fps 时 16.7ms）。接收端发现序号空洞就立即请求重传。
- **FEC**：Reed-Solomon（`klauspost/reedsolomon`），按一帧分组；冗余率随实测丢包率调整（比如丢包 1% → 冗余约 10%，丢包 5% → 约 30%）。遇到突发丢包就做交织。
- 两者结合：FEC 处理零星丢包（不用等重传），NACK 处理 FEC 救不回来的情况。

**拥塞控制 / 带宽估计 —— 低延迟的灵魂**
- 只看丢包的算法要等路由器队列满了才知道拥塞，这时延迟已经涨了上百毫秒（bufferbloat）。
- 应该**看延迟**：接收端计算单向延迟的变化趋势（一组包的到达间隔减去发送间隔）。持续变大说明队列在堆积 → 降码率；平稳 → 小步加码率。这就是 WebRTC GCC 的 trendline 思路。
- 估出来的带宽直接反馈给编码器（目标码率），形成闭环。

**发送节奏控制（Pacer）**
- 一个 4K 关键帧可能有几百个包。如果按网卡速率一次性发出去，会瞬间打满路由器队列、造成自丢包。应该把它们均匀铺开到一帧的时间里发送。
- 配合编码端的 intra-refresh（把关键帧分散到多帧里），码率曲线会更平滑。

**加密**：用 Noise IK 握手（`flynn/noise`，WireGuard 用的就是 Noise），之后每个包用 ChaCha20-Poly1305 加密；用序号做 nonce，并做防重放窗口。

**可观测性**：两端实时统计 RTT、单向延迟、抖动、丢包、乱序、FEC 恢复数、重传数和估计带宽，画成曲线。不测量就没法调优。

## 附录 A：lab/stunprobe/main.go

手写 STUN Binding 客户端：用同一个本地端口问多台 STUN 服务器，比较映射地址来判断 NAT 映射行为。

```go
// stunprobe: 用同一个本地 UDP 端口向多个 STUN 服务器发 Binding Request，
// 比较各服务器看到的公网映射地址，判断 NAT 的映射行为（RFC 4787 / 5780 的思路）。
//
//   映射地址全部相同      → 端点无关映射 (EIM，俗称 cone / NAT1~3)，打洞容易
//   不同服务器端口不同    → 端点相关映射 (EDM，俗称 symmetric / NAT4)，需要端口预测或中继
//
// 用法: go run . [-port 0] [-servers a:3478,b:3478]
package main

import (
	"crypto/rand"
	"encoding/binary"
	"errors"
	"flag"
	"fmt"
	"net"
	"os"
	"strings"
	"time"
)

const magicCookie = 0x2112A442

var defaultServers = []string{
	"stun.miwifi.com:3478",
	"stun.chat.bilibili.com:3478",
	"stun.l.google.com:19302",
	"stun.cloudflare.com:3478",
}

// bindingRequest 构造 20 字节 STUN 头：type=0x0001, length=0, cookie, 96bit 事务 ID。
func bindingRequest() (msg []byte, txid [12]byte) {
	rand.Read(txid[:])
	msg = make([]byte, 20)
	binary.BigEndian.PutUint16(msg[0:], 0x0001)
	binary.BigEndian.PutUint16(msg[2:], 0)
	binary.BigEndian.PutUint32(msg[4:], magicCookie)
	copy(msg[8:], txid[:])
	return
}

// parseMapped 从 Binding Success Response 中取 XOR-MAPPED-ADDRESS（优先）或 MAPPED-ADDRESS。
func parseMapped(b []byte, txid [12]byte) (*net.UDPAddr, error) {
	if len(b) < 20 || binary.BigEndian.Uint16(b[0:]) != 0x0101 {
		return nil, errors.New("not a binding success response")
	}
	if string(b[8:20]) != string(txid[:]) {
		return nil, errors.New("transaction id mismatch")
	}
	var mapped *net.UDPAddr
	attrs := b[20:]
	for len(attrs) >= 4 {
		typ := binary.BigEndian.Uint16(attrs[0:])
		l := int(binary.BigEndian.Uint16(attrs[2:]))
		if 4+l > len(attrs) {
			break
		}
		v := attrs[4 : 4+l]
		switch typ {
		case 0x0020: // XOR-MAPPED-ADDRESS
			if len(v) >= 8 && v[1] == 0x01 {
				port := binary.BigEndian.Uint16(v[2:]) ^ uint16(magicCookie>>16)
				ip := make(net.IP, 4)
				binary.BigEndian.PutUint32(ip, binary.BigEndian.Uint32(v[4:])^magicCookie)
				return &net.UDPAddr{IP: ip, Port: int(port)}, nil
			}
		case 0x0001: // MAPPED-ADDRESS（老服务器）
			if len(v) >= 8 && v[1] == 0x01 {
				mapped = &net.UDPAddr{IP: net.IP(append([]byte(nil), v[4:8]...)), Port: int(binary.BigEndian.Uint16(v[2:]))}
			}
		}
		attrs = attrs[4+(l+3)&^3:] // 属性按 4 字节对齐
	}
	if mapped == nil {
		return nil, errors.New("no mapped address attribute")
	}
	return mapped, nil
}

func query(conn *net.UDPConn, server string) (*net.UDPAddr, time.Duration, error) {
	raddr, err := net.ResolveUDPAddr("udp4", server)
	if err != nil {
		return nil, 0, err
	}
	req, txid := bindingRequest()
	buf := make([]byte, 1500)
	for try := 0; try < 3; try++ { // UDP 会丢，简单重传
		start := time.Now()
		conn.WriteToUDP(req, raddr)
		conn.SetReadDeadline(time.Now().Add(800 * time.Millisecond))
		for {
			n, from, err := conn.ReadFromUDP(buf)
			if err != nil {
				break
			}
			if !from.IP.Equal(raddr.IP) {
				continue
			}
			if m, err := parseMapped(buf[:n], txid); err == nil {
				return m, time.Since(start), nil
			}
		}
	}
	return nil, 0, fmt.Errorf("timeout")
}

func main() {
	port := flag.Int("port", 0, "本地 UDP 端口 (0=随机)")
	servers := flag.String("servers", strings.Join(defaultServers, ","), "逗号分隔的 STUN 服务器")
	flag.Parse()

	conn, err := net.ListenUDP("udp4", &net.UDPAddr{Port: *port})
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	defer conn.Close()
	fmt.Printf("本地地址: %s\n\n", conn.LocalAddr())

	var results []*net.UDPAddr
	for _, s := range strings.Split(*servers, ",") {
		m, rtt, err := query(conn, strings.TrimSpace(s))
		if err != nil {
			fmt.Printf("%-32s  失败: %v\n", s, err)
			continue
		}
		fmt.Printf("%-32s  映射 %-22s  RTT %v\n", s, m, rtt.Round(time.Millisecond))
		results = append(results, m)
	}
	fmt.Println()
	if len(results) < 2 {
		fmt.Println("有效结果不足 2 个，无法判断映射行为")
		return
	}

	sameIP, samePort := true, true
	for _, r := range results[1:] {
		sameIP = sameIP && r.IP.Equal(results[0].IP)
		samePort = samePort && r.Port == results[0].Port
	}
	local := conn.LocalAddr().(*net.UDPAddr).Port
	switch {
	case !sameIP:
		fmt.Println("⚠ 不同服务器看到的公网 IP 不同：多出口/负载均衡 NAT，或部分流量走了代理（检查 sing-box/TUN 分流）")
	case samePort:
		fmt.Printf("✔ 端点无关映射 (EIM / cone)：公网 %s\n", results[0])
		if results[0].Port == local {
			fmt.Println("  且端口保持 (port preserving)，对端可以直接猜到你的端口")
		}
		fmt.Println("  → 与大多数对端 UDP 打洞都能成功。过滤行为(NAT1/2/3)需要 RFC5780 服务器的 CHANGE-REQUEST 才能测。")
	default:
		fmt.Println("✘ 端点相关映射 (EDM / symmetric / NAT4)：每个目的地分配不同端口")
		for i := 1; i < len(results); i++ {
			fmt.Printf("  端口增量 %+d\n", results[i].Port-results[i-1].Port)
		}
		fmt.Println("  → 增量若稳定（如 +1/+2）可做端口预测；随机则只能靠对端是 cone + 生日攻击喷洒，或走中继")
	}
}
```

## 附录 B：lab/punch/main.go

最小化 UDP 打洞：会合服务器 + 对等端，收集所有网卡地址作为候选，支持 `-spray` 端口喷洒、RTT 测量、15 秒保活、聊天模式。

```go
// punch: 最小化的 UDP 打洞实验 —— 一个会合(rendezvous)服务器 + 两个对等端。
// 这就是 ICE/UU远程/RustDesk/Tailscale 打洞的核心骨架，去掉了加密、认证与 TURN 中继。
//
//	服务器 (需要公网 IP，例如一台 VPS):
//	  go run . server -listen :7000
//	两个对等端 (分别在两个不同 NAT 后面):
//	  go run . peer -server VPS:7000 -room demo -id A
//	  go run . peer -server VPS:7000 -room demo -id B
//	对称 NAT 可加 -spray 50 尝试向预测端口附近喷洒。
//
// 协议 (纯文本 UDP):
//
//	peer→server  REG <room> <id> <host1,host2,...>
//	server→peer  PEER <id> <pubaddr> <host1,host2,...>
//	peer↔peer    PUNCH <id> / ACK <id> / PING <unixnano> / PONG <unixnano> / MSG <text> / KA
package main

import (
	"bufio"
	"flag"
	"fmt"
	"log"
	"net"
	"os"
	"sort"
	"strconv"
	"strings"
	"sync"
	"time"
)

func main() {
	if len(os.Args) < 2 {
		fmt.Println("usage: punch server|peer [flags]")
		os.Exit(2)
	}
	switch os.Args[1] {
	case "server":
		runServer(os.Args[2:])
	case "peer":
		runPeer(os.Args[2:])
	default:
		fmt.Println("usage: punch server|peer [flags]")
		os.Exit(2)
	}
}

// ---------------- rendezvous server ----------------

type member struct {
	pub, lan string
	seen     time.Time
}

func runServer(args []string) {
	fs := flag.NewFlagSet("server", flag.ExitOnError)
	listen := fs.String("listen", ":7000", "UDP 监听地址")
	fs.Parse(args)

	conn, err := net.ListenUDP("udp", mustResolve(*listen))
	if err != nil {
		log.Fatal(err)
	}
	log.Printf("rendezvous listening on %s", conn.LocalAddr())
	rooms := map[string]map[string]*member{}
	buf := make([]byte, 1500)
	for {
		n, from, err := conn.ReadFromUDP(buf)
		if err != nil {
			continue
		}
		f := strings.Fields(string(buf[:n]))
		if len(f) != 4 || f[0] != "REG" {
			continue
		}
		room, id, lan := f[1], f[2], f[3]
		if rooms[room] == nil {
			rooms[room] = map[string]*member{}
		}
		m := rooms[room]
		if old, ok := m[id]; !ok || old.pub != from.String() {
			// 服务器看到的源地址 = 对方 NAT 分配的公网映射，这正是 STUN 做的事
			log.Printf("room=%s id=%s pub=%s lan=%s", room, id, from, lan)
		}
		m[id] = &member{pub: from.String(), lan: lan, seen: time.Now()}
		for oid, o := range m {
			if oid == id || time.Since(o.seen) > 30*time.Second {
				continue
			}
			// 双向交换：两边几乎同时拿到对方地址，同时开始往外发包 —— "同时打开"
			conn.WriteToUDP([]byte(fmt.Sprintf("PEER %s %s %s", oid, o.pub, o.lan)), from)
			conn.WriteToUDP([]byte(fmt.Sprintf("PEER %s %s %s", id, from, lan)), mustResolve(o.pub))
		}
	}
}

// ---------------- peer ----------------

func runPeer(args []string) {
	fs := flag.NewFlagSet("peer", flag.ExitOnError)
	server := fs.String("server", "127.0.0.1:7000", "会合服务器地址")
	room := fs.String("room", "demo", "房间名")
	id := fs.String("id", "A", "本端 ID")
	port := fs.Int("port", 0, "本地 UDP 端口 (0=随机)")
	spray := fs.Int("spray", 0, "对称 NAT: 向对端公网端口 ±N 范围喷洒")
	timeout := fs.Duration("timeout", 15*time.Second, "打洞超时")
	fs.Parse(args)

	conn, err := net.ListenUDP("udp4", &net.UDPAddr{Port: *port})
	if err != nil {
		log.Fatal(err)
	}
	srv := mustResolve(*server)
	lan := hostCandidates(conn.LocalAddr().(*net.UDPAddr).Port)
	log.Printf("local %s, registering to %s", lan, srv)

	var (
		mu         sync.Mutex
		candidates []*net.UDPAddr
		selected   *net.UDPAddr
		peerID     string
		connected  = make(chan struct{})
		once       sync.Once
		pongs      = make(chan time.Duration, 64)
	)
	choose := func(a *net.UDPAddr, why string) {
		once.Do(func() {
			mu.Lock()
			selected = a
			mu.Unlock()
			kind := "公网 (打洞成功)"
			if a.IP.IsPrivate() || a.IP.IsLoopback() {
				kind = "局域网直连"
			}
			log.Printf("✔ connected to %s via %s [%s, %s]", peerID, a, kind, why)
			close(connected)
		})
	}

	// 接收循环：一个 socket 同时处理服务器与对端的报文 —— 打洞必须复用同一个端口
	go func() {
		buf := make([]byte, 1500)
		for {
			n, from, err := conn.ReadFromUDP(buf)
			if err != nil {
				return
			}
			msg := string(buf[:n])
			f := strings.Fields(msg)
			if len(f) == 0 {
				continue
			}
			switch f[0] {
			case "PEER":
				if len(f) != 4 {
					continue
				}
				mu.Lock()
				if peerID == "" {
					peerID = f[1]
					pub := mustResolve(f[2])
					log.Printf("peer %s: pub=%s host=%s", f[1], pub, f[3])
					candidates = append(candidates, pub)
					for _, h := range strings.Split(f[3], ",") {
						if h != pub.String() {
							candidates = append(candidates, mustResolve(h))
						}
					}
					for d := -*spray; d <= *spray; d++ {
						if d != 0 && pub.Port+d > 0 && pub.Port+d < 65536 {
							candidates = append(candidates, &net.UDPAddr{IP: pub.IP, Port: pub.Port + d})
						}
					}
				}
				mu.Unlock()
			case "PUNCH":
				conn.WriteToUDP([]byte("ACK "+*id), from)
				choose(from, "收到对方 PUNCH")
			case "ACK":
				choose(from, "收到 ACK")
			case "PING":
				conn.WriteToUDP([]byte("PONG "+f[1]), from)
			case "PONG":
				if t, err := strconv.ParseInt(f[1], 10, 64); err == nil {
					pongs <- time.Since(time.Unix(0, t))
				}
			case "MSG":
				fmt.Printf("\r<%s> %s\n> ", peerID, strings.TrimPrefix(msg, "MSG "))
			}
		}
	}()

	// 注册 + 打洞循环
	deadline := time.Now().Add(*timeout)
	tick := time.NewTicker(200 * time.Millisecond)
loop:
	for {
		select {
		case <-connected:
			break loop
		case <-tick.C:
			if time.Now().After(deadline) {
				log.Fatal("✘ 打洞超时：双方可能都是对称 NAT 或 UDP 被封，现实中这里会降级到 TURN 中继")
			}
			conn.WriteToUDP([]byte(fmt.Sprintf("REG %s %s %s", *room, *id, lan)), srv)
			mu.Lock()
			for _, c := range candidates {
				conn.WriteToUDP([]byte("PUNCH "+*id), c)
			}
			mu.Unlock()
		}
	}
	tick.Stop()

	mu.Lock()
	peer := selected
	mu.Unlock()

	// 测 RTT
	var rtts []time.Duration
	for i := 0; i < 20; i++ {
		conn.WriteToUDP([]byte(fmt.Sprintf("PING %d", time.Now().UnixNano())), peer)
		select {
		case r := <-pongs:
			rtts = append(rtts, r)
		case <-time.After(time.Second):
		}
		time.Sleep(100 * time.Millisecond)
	}
	if len(rtts) > 0 {
		sort.Slice(rtts, func(i, j int) bool { return rtts[i] < rtts[j] })
		log.Printf("RTT: min %v  p50 %v  max %v  loss %d/20",
			rtts[0].Round(time.Microsecond*100), rtts[len(rtts)/2].Round(time.Microsecond*100),
			rtts[len(rtts)-1].Round(time.Microsecond*100), 20-len(rtts))
	}

	// NAT 映射会过期（常见 30s~5min），必须保活
	go func() {
		for range time.Tick(15 * time.Second) {
			conn.WriteToUDP([]byte("KA"), peer)
		}
	}()
	fmt.Print("聊天模式，输入文字回车发送 (Ctrl-C 退出)\n> ")
	sc := bufio.NewScanner(os.Stdin)
	for sc.Scan() {
		conn.WriteToUDP([]byte("MSG "+sc.Text()), peer)
		fmt.Print("> ")
	}
}

func mustResolve(s string) *net.UDPAddr {
	a, err := net.ResolveUDPAddr("udp4", s)
	if err != nil {
		log.Fatalf("resolve %s: %v", s, err)
	}
	return a
}

// hostCandidates 像 ICE 一样收集本机所有网卡的 IPv4 地址作为 host 候选。
// 不能只取"默认路由的地址"：开着 TUN 代理 (sing-box/Clash) 时那是虚拟网卡地址，对端根本不可达。
func hostCandidates(port int) string {
	var out []string
	ifaces, _ := net.Interfaces()
	for _, ifc := range ifaces {
		if ifc.Flags&net.FlagUp == 0 || ifc.Flags&net.FlagLoopback != 0 {
			continue
		}
		addrs, _ := ifc.Addrs()
		for _, a := range addrs {
			if ipn, ok := a.(*net.IPNet); ok && ipn.IP.To4() != nil {
				out = append(out, fmt.Sprintf("%s:%d", ipn.IP, port))
			}
		}
	}
	if len(out) == 0 {
		out = append(out, fmt.Sprintf("127.0.0.1:%d", port))
	}
	return strings.Join(out, ",")
}
```
