## 02 · NAT 穿透（打洞）原理

### 1. 问题本质

家里的电脑没有公网 IP，路由器（以及运营商的 CGNAT）做了地址转换。外面的人**主动**发进来的包，NAT 不知道该给谁，直接丢弃。
打洞的核心思想只有一句话：**让双方同时往外发包，各自在自己的 NAT 上"开门"，让对方的包看起来像"回复"。**

### 2. NAT 行为分类（RFC 4787，比老的 NAT1~4 更准确）

要分开看两个维度：

**映射行为（Mapping）**：同一个内网 `IP:端口` 发往不同目的地时，公网端口变不变？
- **EIM 端点无关映射**：不变 → 对端能用 STUN 查到的端口连进来 ✅
- **EDM/ADM 端点相关映射**（俗称"对称型 NAT4"）：每个目的地换一个端口 → STUN 看到的端口对对端没用 ❌

**过滤行为（Filtering）**：谁能往这个映射里发包？
- EIF 任何人都能发（全锥 NAT1）
- ADF 我发过的 IP 才能回（限制锥 NAT2）
- APDF 我发过的 IP:端口 才能回（端口限制锥 NAT3）

| 本端 \ 对端 | NAT1 | NAT2 | NAT3 | NAT4 对称 |
|---|---|---|---|---|
| NAT1 | ✅ | ✅ | ✅ | ✅ |
| NAT2 | ✅ | ✅ | ✅ | ✅ |
| NAT3 | ✅ | ✅ | ✅ | ⚠ 端口预测 |
| NAT4 | ✅ | ✅ | ⚠ 端口预测/喷洒 | ❌ 基本只能中继 |

你的网络实测（`lab/stunprobe`，2026-10-16）：中国移动公网 `183.197.x.x`，**EIM**，四台 STUN 映射同一端口 → 属于 NAT1~3，和绝大多数对端都能直连。

### 3. 标准流程：STUN / TURN / ICE

- **STUN**（RFC 8489）：一个 20 字节头的 UDP 请求，服务器把"它看到的源地址"放进 `XOR-MAPPED-ADDRESS` 回给你。`lab/stunprobe/main.go` 用不到 150 行手写了它。
- **TURN**（RFC 8656）：中继。你在服务器上申请一个公网端口，所有数据经它转发。永远能通，但费带宽。开源实现 `coturn`。
- **ICE**（RFC 8445）：把 host / srflx / relay 候选两两配对、按优先级做连通性检查、选最优路径。WebRTC 就是 ICE + DTLS + SRTP/SCTP。

### 4. 对付对称 NAT 的技巧

1. **端口预测**：很多 NAT 按顺序分配端口（+1、+2）。先连两台 STUN 看增量，猜下一次的端口。
2. **端口喷洒 / 生日攻击**（Tailscale 用的）：对称端开 256 个 socket，锥形端向对方公网 IP 的随机端口发约 1000 个包——由生日悖论，命中概率很高。`lab/punch -spray N` 是最简化的版本。
3. **UPnP-IGD / NAT-PMP / PCP**：让路由器主动开端口映射（很多家用路由器支持，但 CGNAT 后没用）。
4. **IPv6**：国内宽带和 4G/5G 普遍有全球单播 IPv6，没有 NAT，只有状态防火墙——双方同时发包即可打通，成功率极高。**自研时务必把 IPv6 候选放在最高优先级。**
5. **TCP 打洞**（同时 SYN）：成功率远低于 UDP，只作为 UDP 被 QoS 时的备选。

### 5. 国内网络的特殊情况

- **CGNAT**：运营商给你 `100.64.0.0/10` 地址，外面还有一层 NAT，通常是对称型。可打电话要公网 IP（电信最容易）。
- **光猫路由模式 + 自家路由器 = 双层 NAT**：改光猫桥接、路由器拨号，常能直接变 NAT1。
- **运营商 UDP QoS**：大流量 UDP 可能被限速或丢包，晚高峰明显——这是 FEC 与码率自适应要解决的问题。
- **NAT 映射超时**：UDP 映射常在 30 秒~5 分钟内过期，必须**每 15~25 秒发保活包**（`lab/punch` 里的 `KA`）。
- **本机多网卡 / TUN 代理**：开着 sing-box/Clash TUN 时，"默认出口地址"是虚拟网卡地址（实测本机得到 `172.18.0.1`）。必须像 ICE 一样收集所有网卡地址，并让 P2P 流量绕过代理（不然 STUN 看到的是代理服务器的出口地址）。
